### 2.3 Why-Why — ทำไมโพสต์ Facebook ไม่เคยขึ้นสักครั้ง

```
อาการ    ขั้น "พิมพ์ hashtag ตามลิสต์" ของ Facebook ล้มทุกครั้ง
ทำไม 1   ตัวรันโยน StepError "ไม่มีแฮชแท็กตัวไหนผ่านเกณฑ์เลย"
ทำไม 2   ทุกแท็กถูกตัดสินว่า "ไม่ผ่าน" แล้วโดนลบทิ้งทีละตัว
ทำไม 3   hashtag.passes(count, min) คืน False เพราะ count เป็น None
ทำไม 4   _mention_count_for() หา "ยอดพูดถึง" ท้ายแถวตัวเลือกไม่เจอ
ทำไม 5   Facebook ไม่ได้โชว์ยอดพูดถึงข้างตัวเลือกแฮชแท็ก — นั่นเป็นของ Shopee

รากเหง้า  เอาขั้นตอนที่เขียนไว้สำหรับหน้าจอ Shopee ไปใช้กับหน้าจอ Facebook
          ซึ่งไม่มีตัวเลขให้อ่านตั้งแต่แรก

ทำไมถึงไม่รู้ตัว  ผังของ Facebook ถูกเทรนพิกัดไว้แล้ว แต่ยังไม่เคยสั่งเดินจริงจนจบ
          (run.json ทั้ง 27 ไฟล์ status เป็น pending หมด) จึงไม่มี log ของการล้ม
```

**Corrective** — เพิ่มชนิดขั้นใหม่ `type_tags` (พิมพ์แท็กที่คัดไว้แล้ว ไม่อ่านยอด)
แล้วย้ายผังของทั้ง 2 เครื่องที่บันทึกไว้แล้วให้มาใช้ตัวใหม่

**Preventive** — เพิ่ม `_upgrade_sequence()` ใน `FlowStore._target()`
เพราะผังของแต่ละเครื่องถูก **คัดลอก** จากค่าตั้งต้นตั้งแต่ครั้งแรกที่เปิดใช้
การแก้ค่าตั้งต้นในโค้ดทีหลัง **ไม่มีผลกับเครื่องที่ตั้งไปแล้ว** ถ้าไม่มีตัวนี้
คำว่า "แก้แล้ว" จะจริงเฉพาะเครื่องที่ยังไม่เคยใช้ ส่วนเครื่องจริงยังพังเหมือนเดิม

### 2.4 Why-Why — ทำไม `git diff` ของ `clip_app.py` บวมจนรีวิวไม่ได้

```
อาการ    git diff --stat ของ clip_app.py = 8,707 บรรทัด ทั้งที่ไฟล์มี 5,675 บรรทัด
ทำไม 1   git มองว่าทุกบรรทัดในไฟล์เปลี่ยนหมด
ทำไม 2   ไฟล์ใน git เป็น CRLF (3,032 บรรทัด) แต่ไฟล์บนดิสก์เป็น LF ล้วน
ทำไม 3   มีสคริปต์เขียนไฟล์ทั้งก้อนด้วย read_text/write_text ซึ่งแปลงตัวขึ้นบรรทัด
รากเหง้า  เขียนไฟล์เป็นข้อความแทนที่จะเขียนเป็นไบต์ (กติกา CLAUDE.md 7.6 เตือนไว้แล้ว)
```

**Corrective** — แปลงกลับเป็น CRLF ให้ตรงกับ git ทั้ง `clip_app.py` และ `publish_flow.py`
(เจอว่า `publish_flow.py` ก็โดนเหมือนกัน 1,351/1,139 → **224/12**)

**Preventive** — กติกามีอยู่แล้วใน CLAUDE.md 7.6 แต่ไม่มีใครทำตาม
**ข้อเสนอ: เพิ่ม `.gitattributes` ตรึงตัวขึ้นบรรทัดรายไฟล์** จะได้ไม่ต้องพึ่งความจำ
(ยังไม่ได้ทำ — อยู่ในงานค้าง)
