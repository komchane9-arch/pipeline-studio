### 1.2 โควตา Gemini ชั้นฟรีแยกถังรายโมเดล

คำตอบ 429 บอกเพดานจริงมาด้วย

```json
{"quotaId": "GenerateRequestsPerDayPerProjectPerModel-FreeTier",
 "quotaDimensions": {"model": "gemini-3.5-flash"}, "quotaValue": "20"}
```

**20 ครั้ง/วัน/โมเดล** — และคำว่า `FreeTier` แปลว่า **คีย์ที่ใช้อยู่ยังผูกกับ
โปรเจกต์ที่ไม่ได้เปิดการเรียกเก็บเงิน** ทั้งที่เจ้าของเติมเงินไว้แล้ว
เงินที่เติมจึงไม่ได้ถูกใช้ (เป็นงานที่เจ้าของต้องเข้าไปเปิด Billing เอง)

### 1.3 หน้าเว็บล้นจอ — ไล่ 4 รอบกว่าจะเจอ

อาการที่ผู้ใช้แจ้งต่อกัน 3 ครั้ง
*"เลื่อนซ้ายขวาไม่ได้"* → *"ไม่เห็นปุ่มตั้งค่า"* → *"มองไม่เห็น เลื่อนมาตรงกลางๆหน่อย"*

**สาเหตุคนละตัวกันทุกครั้ง แต่อาการเหมือนกันหมด**

| # | ตัวที่ดัน | หลักฐาน |
|---|---|---|
| 1 | กระดาน 7 กอง | ความกว้างขั้นต่ำฝั่งขวา 1002px → ถอดกระดานเหลือ 270px |
| 2 | ชิปสถานะบนหัวจอ | ยาวขึ้นตามจำนวนมือถือ ดันปุ่มท้ายแถวตกขอบ |
| 3 | **ขอบที่ผมใส่เองรอบแรก** | จอ 4K: ฝั่งทำงาน 2759px → **691px** |

**ข้อ 3 คือความผิดผมเต็มๆ** — ผู้ใช้บอก "ไม่ต้องอยู่ริมมาก" ผมไปตั้ง
`max-width: 1680px` ตายตัว ซึ่งบนจอ 4K (3792px) ทำให้ฝั่งทำงานเหลือ 691px
ช่องพาธไฟล์กับชื่อสินค้าถูกตัด = อาการ "มองไม่เห็น" ที่เขาเจอ
**จอยิ่งใหญ่ยิ่งพัง** เพราะขอบโตตามส่วนต่างจาก 1680 ไปเรื่อยๆ

### 1.4 ทำไมตัววัดของผมบอกว่า "ปกติ" ทั้งที่พัง — 4 รอบติด

| รอบ | วัดอะไร | พลาดเพราะ |
|---|---|---|
| 1 | ตัวทดสอบในกล่องกว้างคงที่ | `46vw` คิดจาก viewport ที่ Browser pane รายงานเป็น **0** |
| 2 | หน้าจริงที่จอ 1990 | จอเล็กกว่าผู้ใช้ครึ่งหนึ่ง ขอบเลยยังไม่กินพื้นที่ |
| 3 | เช็ค "ล้นออกนอกหน้าต่าง" | **ผิดเกณฑ์** ของถูกบีบอยู่ในกรอบ ไม่ได้ล้นออกนอกจอ |
| 4 | ตั้ง `--phone-col` ที่ราก | **ผิดที่** ของจริงตั้งที่ `body` |

ตรงกับกติกาข้อ 2.3 เป๊ะ — ตัวตรวจที่บอกว่าผ่านทั้งที่ยังไม่ผ่าน อันตรายกว่าไม่มี

### 1.5 "เลื่อนลงล่างสุดไม่ได้" — ไม่มีบั๊ก ผมเกือบรายงานผิด

จอกว้าง ≥901px ออกแบบไว้ให้ **ทั้งหน้าไม่เลื่อน** (`body { overflow: hidden }`)
แล้วให้ `.phone-panel` / `.process-panel` เลื่อนของตัวเองแยกกัน

ผมสั่ง `window.scrollTo` แล้วเห็นไม่ขยับ เลยนึกว่าพัง — พอเลื่อนให้ถูกตัว
**ทุกระดับซูมถึงล่างสุดครบทั้งสองฝั่ง ชิ้นสุดท้ายมองเห็นหมด**

### 1.6 ตัวกรองโปรเซสหลวมเกินไป — ผมพลาดซ้ำรอยที่โปรเจกต์บันทึกไว้แล้ว

รายงานว่าเจอ clip_app 2 ตัว **ผิด** — ตัวที่สองคือคำสั่งตรวจไวยากรณ์ของผมเอง

```
python -c "import ast,sys; ast.parse(...)" clip_app.py    ← โดนนับเป็นเซิร์ฟเวอร์
```

ตัวกรอง `-like '*clip_app.py*'` จับ **ทุกคำสั่งที่เอ่ยชื่อไฟล์** ไม่ใช่แค่ตัวที่รันไฟล์นั้น
พิสูจน์ด้วยการทำซ้ำ: ตัวกรองเดิมเห็น 2 ตัว · ตัวกรองที่ถูกเห็น 1 ตัว

`restart_studio.py` ปลอดภัยอยู่แล้ว (เล็งด้วยเจ้าของพอร์ต + มีรายชื่อห้ามแตะ)

## 2. สรุปผลงานทั้งหมดในแชทนี้

### 2.1 ขั้นตอนใหม่ — ให้ Gemini กรองก่อนถึงมือคน

`shopee_scrape.curate_for_ad()` + เสียบใน `shopee_service.shopee_collect()`

**ของเดิมเป็นสองงานที่ไม่รู้จักกัน**

```
judge_images()      ดูรูปอย่างเดียว   → เลือกรูป    (ไม่รู้ว่าสินค้ามีดีอะไร)
analyse_features()  อ่านข้อความอย่างเดียว → จุดเด่น  (ไม่รู้ว่ารูปมีอะไรให้ดู)
```

รูปที่เลือกกับจุดเด่นที่เขียนจึงไม่เกี่ยวกันเลย — คลิปพูดถึงของที่คนดูไม่เห็น

รวมเป็นครั้งเดียว Gemini เห็นทั้งรูปและรายละเอียดพร้อมกัน จับคู่ได้ว่า
**"จุดขายข้อนี้ ดูได้จากรูปใบนี้"** และประหยัดโควตาจาก 2 ครั้ง เหลือ 1 ครั้ง

คำสั่งตามที่ผู้ใช้กำหนด — *"ให้คิดว่าตัวเองเป็นนักสร้างวีดีโอที่เก่งที่สุดในโลก
ที่สามารถทำยอดวิวได้ 1 ล้านวิว ให้เลือกรูปมาจำนวน 3-5 รูป เพื่อดึงจุดเด่นทั้งหมด
ของสินค้านี้ และนำจุดเด่นมาอธิบายเป็นภาษาโฆษณาที่เข้าใจได้ทีละข้อตามจำนวนรูป"*

ผลจริง

```
12:41:23  ส่งรูป 23 ใบ + รายละเอียด ให้ Gemini กรองให้ก่อน…
12:42:46  เลือกรูปที่ [8, 13, 15, 18, 19] พร้อมคำโฆษณา 5 ข้อ · ไล่จุดขายได้ 9 ข้อ
12:42:46  Gemini คัดเหลือ 5 ใบจาก 23 ใบ — รอคุณกดอนุมัติ
```

ตัวอย่างคำโฆษณาที่ได้ (เก้าอี้ CHICAGO) — ทุกข้ออ้างของที่มีจริงในหน้าขาย

> **นั่งสบายหรูหรา รองรับน้ำหนักได้ถึง 150 กิโลกรัม อุ่นใจด้วยรับประกัน 1 ปี**
> └ เห็นในรูป: ภาพเก้าอี้จัดวางจริง พร้อมสัญลักษณ์รับประกัน

⚠️ **ผมวางโค้ดผิดสาขารอบแรก** ไปวางใน `want_all=False` แต่สายคลิปเรียกด้วย
`want_all=True` เสมอ → **ล้มเงียบไม่มี log สักบรรทัด** (12:27 น.)
เขียนคอมเมนต์เตือนไว้ในโค้ดแล้ว

### 2.4 `/clips` กรองเหลือเฉพาะที่พร้อมลง Shopee

ผู้ใช้สั่ง — *"ในนี้จะต้องมีแค่งานที่มีคลิปแล้ว แล้วรอลง shopee video เท่านั้น"*

```

กรองออก: story 61 · clip 5 (ยังไม่มีคลิป)
```

ใช้ `clip_board.bucket_of_run()` ตัวเดียวกับกระดานบนหน้าเว็บ ห้ามเขียนเงื่อนไขซ้ำ

⚠️ **กับดักที่เกือบพลาด** — `/clip <เลข>` นับจากรายการเต็ม ถ้ากรองแค่ฝั่งแสดงผล
พิมพ์ `/clip 2` จะเปิดสินค้าคนละตัว แก้ให้ทั้งสองที่นับจากรายการเดียวกันแล้ว
(`_clips_ready()`) ส่วนการเปิดด้วยรหัสสินค้ายังหาได้จากทุกงานเหมือนเดิม

## 5. คำสั่งที่รันจริงและผลที่วัดได้

**ตรวจหน้าเว็บทุกระดับซูมใน Chrome ตัวจริง** — Playwright `channel="chrome"`,
`launch_persistent_context` ด้วยโปรไฟล์ชั่วคราว (ไม่แตะ `flow_browser_profile`),
เปลี่ยน viewport เป็น `หน้าต่าง ÷ ซูม` ซึ่งเทียบเท่าการซูมจริงในแง่การจัดหน้า
→ ล้น 0 ทุกระดับ · ปุ่มเห็นทุกระดับ · เลื่อนถึงล่างสุดทุกระดับ

**ทำซ้ำบั๊กตัวกรองโปรเซส**

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'python\.exe"?\s+"?[^"]*clip_app\.py"?\s*$' }
```

→ ตัวกรองถูกเห็น 1 ตัว · ตัวกรองหลวม (`-like '*clip_app.py*'`) เห็น 2 ตัว

**เก็บกวาดหลังทดสอบทุกครั้ง** — ปิดพอร์ตทดสอบ 8991 · ลบไฟล์ harness 3 ไฟล์ ·
ลบโปรไฟล์ Chrome ชั่วคราว · เก็บ `adb` ค้างรวม 4 รอบ (6–9 ตัวต่อรอบ)
