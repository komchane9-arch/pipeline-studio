## 2. หลักฐานจากของจริง

### 2.1 ภาพหน้าจอที่ระบบเก็บเอง

```
data/evidence/20260910-213226-publish-facebook_reels create_reel ผ่าน.png
data/evidence/20260910-213324-publish-facebook_reels latest_clip ผ่าน.png
```

ภาพแรกคือหน้าเลือกสื่อของ Facebook มีของอยู่ 2 ช่อง

```
ช่อง 1 (ซ้าย)  รูปสายชาร์จ USB
ช่อง 2 (ขวา)   คลิปเก้าอี้ · ป้ายบอกความยาว 00:10
```

### 2.2 ผังจอบอกไว้ชัดเจนอยู่แล้ว

```
[0,422][240,739]    สร้างคลิป Reels ด้วย รูปภาพ, รายการที่ 1, ถ่ายเมื่อ ก.ย. 10, 2026 16:43
[242,422][480,739]  สร้างคลิป Reels ด้วย วิดีโอ,  รายการที่ 2, ถ่ายเมื่อ ก.ย. 10, 2026 21:31, 00:10
```

**Facebook เขียนคำว่า "รูปภาพ" กับ "วิดีโอ" ติดไว้กับทุกช่อง** และคลิปยังมีป้าย
ความยาว `00:10` เพิ่มมาอีก — ข้อมูลที่ต้องใช้ตัดสินอยู่บนจอครบตั้งแต่แรก
**แต่โค้ดไม่เคยอ่านมันเลย**

### 2.3 พิกัดที่แตะ

```
21:33:24  5. เลือกคลิปที่จะโพสต์ — ✓ แตะที่ 99, 595 (พิกัดที่เทรนไว้)
```

`(99, 595)` ตกอยู่ในกรอบ `[0,422][240,739]` = **ช่องที่ 1 = รูปภาพ**

### 2.4 ตัวส่งคลิปทำงานถูกต้อง ไม่ได้พัง

```
21:31:11 [facebook_reels] ล้างคลิปเก่าก่อนรับใบใหม่แล้ว — ไฟล์และ MediaStore ว่าง
21:31:17 ✓ ... คลิปอยู่ในเครื่องแล้วและเป็นใบล่าสุด: 27425821220-clip.mp4 (3.3 MB)
```

คลิปเข้าเครื่องเรียบร้อย และเป็นใบล่าสุดจริง **แต่ Facebook ไม่ได้วางไว้ช่องแรก**

## 3. ไล่ "ทำไม" จนถึงราก

| ชั้น | คำถาม | คำตอบจากของจริง |
|---|---|---|
| 1 | ทำไมโพสต์เป็นรูป | ขั้นที่ 5 แตะช่องที่ 1 ซึ่งเป็นรูป |
| 2 | ทำไมแตะช่องที่ 1 | ขั้นนี้เป็น **การแตะพิกัดตายตัว** ไม่ได้อ่านว่าช่องนั้นคืออะไร |
| 3 | ทำไมช่องที่ 1 ไม่ใช่คลิป | ลำดับของ Facebook **เอาแน่ไม่ได้** วัดแล้ว 4 ใน 13 ครั้งเป็นรูป |
| 4 | ทำไมไม่มีอะไรฟ้อง | ตัวตรวจถามว่า **"หน้าจอเปลี่ยนไหม"** ซึ่งเปลี่ยนทั้งตอนหยิบถูกและหยิบผิด |
| 5 | ทำไมมีรูปอยู่ในเครื่องตั้งแต่แรก | `tiktok_product_link.py` วางรูปสินค้าไว้แล้ว **ไม่เคยเก็บทิ้ง** |

### รากเหง้า

**ขั้น "เลือกคลิปที่จะโพสต์" ตัดสินด้วยตำแหน่ง ไม่ได้ตัดสินด้วยตัวสื่อ**
และตัวตรวจของขั้นนี้ตอบว่า "ใช่" ได้ทั้งตอนสำเร็จและตอนล้มเหลว
— **ตรงกับกติกาข้อ 2.3.1 เป๊ะ**

### ทำไมถึงไม่รู้ตัว (คนละเรื่องกับสาเหตุ)

กลไกที่ควรกันเรื่องนี้มีอยู่แล้วและ**ทำงานถูกทุกใบ** คือ `_clip_sender` ใน `app.py`
ที่ล้างคลิปเก่า ส่งคลิปใหม่ แล้วยืนยันว่า *"เป็นใบล่าสุด"*

**แต่มันยืนยันเทียบกันเฉพาะในหมู่วิดีโอด้วยกัน** ขณะที่หน้าเลือกสื่อของ Facebook
**รวมรูปกับวิดีโอไว้ด้วยกัน** — สมมติฐานที่ว่า "ใบล่าสุด = ช่องที่ 1" จึงผิด
และไม่มีใครรู้เพราะไม่เคยมีใครวัด

## 5. ทางแก้ — Corrective + Preventive

### Corrective (แก้ของที่พังไปแล้ว)

1. **ลบโพสต์ 3 ใบใน Facebook ด้วยมือ** — ระบบลบให้ไม่ได้ตามกติกาข้อ 2.7
2. **ปลดสถานะ `posted` ของ 3 ใบนั้น** ให้กลับไปลงใหม่ได้
   (`26900959329` · `41778159279` · `28225815685`)
3. **เก็บรูปสินค้าค้างในเครื่อง** `/sdcard/Pictures/pipeline-products/7004541327.jpg`
   — เป็นแค่การกันเฉพาะหน้า เพราะงาน TikTok ใบต่อไปจะวางรูปใหม่ทันที

**กู้คืนไม่ได้:** ยอดเข้าถึงและความน่าเชื่อถือของโพสต์ที่ขึ้นไปแล้ว 3 ใบ

### Preventive (กันไม่ให้เกิดซ้ำ)

| # | แก้ที่ไหน | เจ้าของไฟล์ | ทำอะไร |
|---|---|---|---|
| P1 | `publish_flow.py` ขั้น `latest_clip` | **สายโพสต์** | เลิกแตะพิกัดตายตัว ให้อ่านผังจอแล้ว**เลือกช่องที่ป้ายเขียนว่า "วิดีโอ"** |
| P2 | ตัวตรวจของขั้น `latest_clip` | **สายโพสต์** | เปลี่ยนจาก "จอเปลี่ยนไหม" เป็น **"ในหน้าตัดต่อมีแถบเลื่อนความยาวคลิปไหม"** ซึ่งมีเฉพาะตอนเลือกวิดีโอ |
| P3 | `app.py` `_clip_sender` | **ส่วนกลาง** | ตอนยืนยัน "เป็นใบล่าสุด" ให้เทียบ**รวมรูปกับวิดีโอ** ไม่ใช่เทียบเฉพาะวิดีโอ |
| P4 | `tiktok_product_link.py` | **สายคลิป (เรา)** | เก็บรูปทิ้งเมื่อใช้เสร็จ ไม่ทิ้งค้างไว้ในแกลเลอรี |

**P1 คือตัวที่ตอบได้ว่า "ถ้ามีตั้งแต่แรก ปัญหานี้จะไม่เกิด"**
ส่วน P3 กับ P4 เป็นการลดโอกาส ไม่ใช่การปิดประตู เพราะตราบใดที่ยังตัดสินด้วยตำแหน่ง
วันหนึ่งที่ Facebook สลับลำดับเองก็พังอีก

⚠️ **P1–P3 อยู่นอกเลนของแชทนี้** ต้องส่งให้สายโพสต์และสายกลางตัดสิน
แชทนี้แตะได้เฉพาะ P4
