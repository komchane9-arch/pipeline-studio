# เครื่องมือของแผน "สตอรีบอร์ดใส่พรีเซนเตอร์" เขียนเสร็จแล้ว — ยังไม่ได้รัน

ต่อจาก [แผนเต็มเมื่อ 9 ก.ย.](2026-09-09-แผนเจนสตอรีบอร์ดใหม่ทั้งกอง-ใส่พรีเซนเตอร์.md)

เจ้าของสั่งว่า **"เขียน flow ไม่ต้องรันเอง"** — รอบนี้จึงทำให้ flow นั้น
**กดรันได้จริง** โดยยังไม่รัน

> **ยังไม่มีสตอรีบอร์ดใบไหนถูกแตะ · ยังไม่มีการเรียก ChatGPT สักครั้ง**

## 1. ขั้นที่ 1 ของแผน — เก็บของเก่า ✅ เขียนเสร็จ + ทดสอบแล้ว

`tools/archive_storyboards.py`

```bash
python tools/archive_storyboards.py --scope not-generated          # ดูก่อน
python tools/archive_storyboards.py --scope not-generated --apply  # ทำจริง
```

**ทำไมต้องมี** — ตรวจโค้ดแล้วพบว่าของเดิม **ถูกทับทิ้งโดยไม่มีอะไรเตือน**

```
clip_store.save_storyboard()   เขียนทับ run["storyboard"] ทั้งช่อง
chatgpt_driver                 ดาวน์โหลดภาพใหม่ลง storyboard/ ชื่อขึ้นต้น
                               storyboard- เหมือนเดิมทุกประการ
```

ทับแล้วกู้ไม่ได้ เพราะภาพต้นฉบับอยู่บนเซิร์ฟเวอร์ ChatGPT ซึ่งลิงก์หมดอายุ

### เก็บอะไรบ้าง

```
<ใบงาน>/storyboard-เก่า-<วันที่เวลา>/
    storyboard-01.png ...        ภาพเก่าทุกใบ (ย้ายมา ไม่ใช่ก๊อป)
    run-เก่า.json                 สำเนาใบงานก่อนแก้

run.json → storyboard_history[]   ภาพ + คำสั่ง Flow + บทพูด + ลิงก์แชท
data/backup/storyboard-ก่อนใส่พรีเซนเตอร์-<วันที่เวลา>.zip
```

**เก็บสามอย่างพร้อมกัน ไม่ใช่แค่ภาพ** — ภาพ · คำสั่ง Flow · บทพูด ผูกกันเป็นชุดเดียว
เก็บแค่ภาพแล้ววันหนึ่งอยากย้อนกลับ จะย้อนไม่ได้

### ผลทดสอบ (ทดสอบกับข้อมูลจำลอง ไม่แตะ data จริง — กติกาข้อ 7.4)

| ทดสอบ | ผล |
|---|---|
| ใบที่มีภาพ + ยังไม่เจน | ✅ เก็บถูก |
| ใบที่เจนคลิปแล้ว | ✅ ข้าม ไม่ถูกแตะ |
| ใบที่ไม่มีภาพเลย | ✅ ข้าม ไม่ถูกแตะ |

| ประวัติเก็บคำสั่ง Flow + บทพูด | ✅ ครบ |
| ช่องสตอรีบอร์ดถูกล้างให้ว่าง | ✅ (ด่านขั้นที่ 3 จึงยังทำงาน) |
| zip มีทั้งภาพ ใบงาน และ manifest | ✅ |

**หยุดทันทีที่ใบแรกพลาด** ไม่ทำต่อจนพังทั้งกอง และมีตรวจซ้ำหลังทำทุกใบ

## 2. ขั้นที่ 2 ของแผน — กติกาพรีเซนเตอร์ ✅ เขียนเสร็จ + ทดสอบแล้ว

### เปิด/ปิดด้วยการวางรูป ไม่ใช่ช่องติ๊ก

```
วางรูปลง data/presenter/   →  เปิด
เอารูปออก                   →  ปิด
```

**ทำไมไม่ทำเป็นช่องติ๊ก** — กติกาข้อนี้ไม่มีรูปแล้วทำงานไม่ได้ ถ้าแยกเป็นช่องติ๊ก
วันหนึ่งจะมีคนติ๊กเปิดทั้งที่ยังไม่ได้วางรูป แล้ว ChatGPT จะวาดผู้หญิงมั่วขึ้นมา
**คนละคนทุกใบโดยไม่มีอะไรฟ้อง** (รูปแบบเดียวกับกติกาข้อ 2.3.1)

### รูปคนแยกจากรูปสินค้าโดยตั้งใจ

`make_storyboard()` รับพารามิเตอร์ใหม่ `presenter=` แยกต่างหาก

**ถ้ายัดรวมในรูปสินค้า** เลข *"แนบรูปสินค้ามาให้ N ใบ"* จะนับรูปคนเป็นสินค้าไปด้วย
แล้ว GPT จะนึกว่าผู้หญิงคนนั้นคือสินค้าที่ต้องโฆษณา

ข้อความที่ GPT ได้จริง (รูปสินค้า 4 ใบ + พรีเซนเตอร์ 1 ใบ)

```
แนบรูปสินค้าจริงมาให้ 4 ใบ (เรียงเป็นรูปที่ 1–4)
และรูปที่ 5 คือรูปพรีเซนเตอร์ **ไม่ใช่สินค้า**
ข้อบังคับเรื่องพรีเซนเตอร์:
  · เป็นผู้หญิงคนเดียวกันในทุกใบงานของโปรเจกต์นี้
  · ให้เธอปรากฏใน **ฉากแรกกับฉากสุดท้ายเท่านั้น** ฉากกลางไม่ต้องมีคน
  · ท่าทาง: ยืนข้างสินค้า มือเชิญไปทางสินค้า ห้ามถือหรืออุ้มสินค้า
  · **สินค้าต้องยังเห็นครบทั้งชิ้นเหมือนเดิม** ถ้าต้องเลือก ให้เลือกสินค้า
  · อย่าวาดให้หน้าเหมือนดารา นักแสดง หรือบุคคลมีชื่อเสียง
  · ห้ามใส่ชื่อ ยี่ห้อ หรือข้อความบนเสื้อผ้า
```

### แก้คำสั่งที่ขัดกันด้วย

`chatgpt_driver.py` ทางถอยตอนโดนตัวกรองปฏิเสธ เดิมสั่ง
**"ไม่ต้องมีคนหรือโลโก้แบรนด์"** ซึ่งขัดกับกติกาใหม่ตรงๆ — ตัดคำว่าคนออก
เหลือห้ามเฉพาะโลโก้แบรนด์ซึ่งยังต้องห้ามอยู่

### ผลทดสอบ

| ทดสอบ | ผล |
|---|---|
| ไม่มีรูป → กติกาปิด | ✅ |
| วางรูป 1 ใบ → กติกาเปิดเอง | ✅ |
| เอารูปออก → ปิดกลับเอง | ✅ |
| ข้อความตอนไม่มีรูป เหมือนเดิมทุกตัวอักษร | ✅ ของเดิมไม่พัง |
| พรีเซนเตอร์ 1 ใบเขียน "รูปที่ 5" | ✅ ไม่ใช่ "รูปที่ 5–5" |
| พรีเซนเตอร์ 3 ใบเขียน "รูปที่ 5–7" | ✅ |
| เซิร์ฟเวอร์ 8877 โหลดโค้ดใหม่ | ✅ ตอบ 200 |

## 4. บทเรียนของรอบนี้

**เขียนสคริปต์แก้ไฟล์ที่มีขีดกลับ ต้องเขียนเป็นไฟล์ ห้ามพิมพ์ผ่าน heredoc**
รอบนี้โดนซ้ำ 2 ครั้ง — `\n` ในสคริปต์กลายเป็นการขึ้นบรรทัดจริง ทำให้โค้ดที่เขียน
ออกมาพัง เสียเวลาแก้ทั้งสองรอบ

**และ `clip_rules.py` เป็นไฟล์ท้ายบรรทัดแบบ LF** — เผลอเขียนด้วย `write_text`
ทำให้กลายเป็น CRLF ทั้งไฟล์ git รายงานว่าแก้ 384 บรรทัดทั้งที่เพิ่มจริง 63 บรรทัด
(กติกาข้อ 7.6) แก้คืนแล้ว ตอนนี้ diff เหลือ 63 บรรทัดตามจริง
