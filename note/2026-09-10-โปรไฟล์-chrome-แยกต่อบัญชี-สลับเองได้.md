**วันที่** 10 กันยายน 2569
**สั่งโดยเจ้าของ** — *"เอาเลยทำโปรไฟล์แยก"*

## 1. สรุปข้อมูลทั้งหมด

### ทำไมถึงเปลี่ยนแนวจาก "ล็อกอินสลับ" มาเป็น "โปรไฟล์แยก"

เช้าวันนี้เรียนวิธีเปลี่ยนบัญชี Gmail จากเจ้าของจนจบทั้ง 5 ขั้น และล็อกอิน
สำเร็จจริง (บัญชี `ko…e9@gmail.com` เครดิต 1,103) **แต่เจอกำแพงที่แก้ไม่ได้**

| ครั้งที่ | ผลลัพธ์ |
|---|---|
| 1 | Google เด้ง reCAPTCHA — เจ้าของติ๊กให้ |
| 2 | เด้งอีก — เจ้าของติ๊กให้อีก |
| 3 | เด้งอีก — เจ้าของติ๊กให้อีก |

**3 จาก 3 ครั้ง** แปลว่าถ้าใช้วิธีล็อกอินสลับ ระบบจะทำงานตอนกลางคืนเองไม่ได้เลย
ต้องมีคนนั่งเฝ้าติ๊กให้ทุกครั้งที่เครดิตหมด

### วิธีใหม่ตัดปัญหานี้ทิ้งทั้งก้อน

```
วิธีเดิม   เครดิตหมด → ออกจากบัญชี → ล็อกอินใหม่ → เจอ reCAPTCHA → รอคน
วิธีใหม่   เครดิตหมด → เปิด Chrome คนละโฟลเดอร์ → เจนต่อได้เลย
```

**หนึ่งบัญชี = หนึ่งโฟลเดอร์โปรไฟล์** ล็อกอินค้างไว้ในนั้นครั้งเดียวตอนตั้งค่า
หลังจากนั้นการสลับบัญชีคือการเปิดคนละโฟลเดอร์ **ไม่ผ่านหน้าล็อกอินอีกเลย**

ระบบทำแบบนี้อยู่แล้วกับช่องที่ 2 (`flow_browser_profile2` ที่เจ้าของล็อกอินไว้
ตั้งแต่ 30 ส.ค.) งานรอบนี้แค่ขยายให้ครบทุกบัญชี แทนที่จะเขียนชื่อโฟลเดอร์
ตายตัวทีละอัน

### ตัวเลขที่วัดได้จริง

| เรื่อง | ค่า |
|---|---|
| บัญชีที่เก็บไว้ | 7 ใบ |
| โปรไฟล์ที่พร้อมใช้แล้ว | **1 ใบ** (`ko…e9` เครดิต 1,103) |
| ที่เหลือต้องล็อกอินเอง | 6 ใบ · ครั้งเดียวต่อใบ |
| ขนาดโปรไฟล์ที่ใช้อยู่ | 445 MB (`flow_gen_profile`) |
| เนื้อที่ที่ต้องเผื่อถ้าครบ 7 ใบ | ราว 2–3 GB |
| เกณฑ์สลับบัญชี | เครดิตเหลือน้อยกว่า 15 (= 1 คลิป) |

**ใบแรกไม่ต้องล็อกอินซ้ำ** เพราะผูกเข้ากับโฟลเดอร์ `flow_gen_profile`
ที่ล็อกอินค้างอยู่แล้ว ประหยัดไป 1 รอบ

## 2. สรุปผลงานทั้งหมดในแชทนี้ (ช่วงโปรไฟล์แยก)

### `flow_accounts.py` — ทะเบียนบัญชีรู้จักโปรไฟล์แล้ว

| เพิ่มอะไร | ทำอะไร |
|---|---|
| `PROFILES_DIR` | โฟลเดอร์แม่ `data/flow_profiles/` |
| `profile_slug()` | ชื่อโฟลเดอร์จากอีเมล เช่น `komchanc9` |
| `profile_dir_of()` | โฟลเดอร์ของบัญชีนี้ (ตั้งชื่อเองในทะเบียนได้ ตัวนั้นชนะ) |
| `set_profile()` | ผูกบัญชีกับโฟลเดอร์ที่มีอยู่แล้ว |
| `set_ready()` | จดว่า "ล็อกอินค้างไว้แล้ว" — **จดแยกจาก "มีรหัสผ่านเก็บไว้"** |
| `profile_used()` | โฟลเดอร์นี้ Chrome เคยเปิดจริงไหม (ดู `Default/Preferences`) |
| `is_ready()` | ธงต้องขึ้น **และ** โฟลเดอร์ต้องยังอยู่จริง |
| `ready_accounts()` | รายชื่อใบที่พร้อมใช้ |

`next_account()` เลือก **ใบที่โปรไฟล์พร้อมก่อนเสมอ** — ไม่งั้นจะสลับไปโฟลเดอร์
ว่างเปล่าแล้วเจนไม่ได้ทั้งกองโดยไม่มีอะไรฟ้อง

### `flow_worker.py` — ช่องที่ 1 ใช้โฟลเดอร์ของบัญชีที่กำลังใช้อยู่

`flow_seat(1)` เดิมคืนโฟลเดอร์ตายตัวเสมอ ตอนนี้ถามทะเบียนก่อนว่าบัญชี
ที่กำลังใช้อยู่มีโปรไฟล์พร้อมไหม — มีก็ใช้อันนั้น ไม่มีก็ถอยไปของเดิม

⚠️ **ชื่อล็อกตามโฟลเดอร์เสมอ** โฟลเดอร์ใหม่ได้ชื่อ `flow-acct-<ชื่อโฟลเดอร์>`
ส่วนโฟลเดอร์เดิมได้ชื่อเดิม `flow-gen` เป๊ะๆ — ถ้าโฟลเดอร์เดียวกันได้ชื่อล็อก
สองแบบ สองงานจะเปิด Chrome ทับกันบนโปรไฟล์เดียวโดยคิดว่าตัวเองกันกันอยู่

**ช่องที่ 2 ไม่ถูกแตะเลย** ยังเป็น `flow_browser_profile2` เหมือนเดิม

### `flow_login.py` — คำสั่งตั้งค่าโปรไฟล์ครั้งแรก

```bash
python flow_login.py โปรไฟล์ --ดู       # ดูว่าใบไหนพร้อมแล้วบ้าง
python flow_login.py โปรไฟล์            # ไล่ตั้งค่าทุกใบที่ยังไม่พร้อม
python flow_login.py โปรไฟล์ --อีเมล x@gmail.com --นาที 20
```

เปิดหน้าต่าง Chrome ของโฟลเดอร์นั้นค้างไว้ **ให้เจ้าของล็อกอินเอง** แล้วเช็คให้
ทุก 15 วินาทีว่าเข้าได้หรือยัง — **ไม่พิมพ์รหัสผ่านให้** ตั้งใจ เพราะ reCAPTCHA
เด้งอยู่ดี พิมพ์ให้ก็ยังต้องรอคนติ๊ก

**ตัวตรวจต้องผ่านครบ 2 อย่างถึงจะนับว่าพร้อม** (กติกาข้อ 2.3.1)

1. **อ่านยอดเครดิตบนหน้า Flow ได้เป็นตัวเลข** — เลขนี้ขึ้นเฉพาะตอนล็อกอินแล้ว
   และ Flow ยอมให้ใช้จริง ไม่ใช่แค่ "ไม่เห็นปุ่ม Sign in"
2. **ชื่อบัญชีบนหน้าตรงกับใบที่ตั้งใจ** — ขาดข้อนี้ โปรไฟล์ 7 ใบอาจเป็น
   บัญชีเดียวกันทั้งหมด แล้วการสลับจะไม่ได้อะไรเลย

`account_on_page()` อ่านอีเมลจากป้ายปุ่มรูปโปรไฟล์มุมขวาบน
(`aria-label="บัญชี Google: ชื่อ (someone@gmail.com)"`)

**"อ่านชื่อไม่ได้" ไม่เท่ากับ "บัญชีผิด"** — แยกสองอย่างนี้ออกจากกัน
ทั้งคู่ไม่ผ่าน แต่ข้อความบอกคนละอย่าง

### `clip_app.py` — สลับบัญชีเองได้จริงแล้ว

ข้อ 2 ของคำสั่งเดิม (*"ถ้าเหลือน้อยกว่า 15 ให้ทำการเปลี่ยน email"*) เดิมทำได้
แค่ **หยุดแล้วบอก** เพราะยังไม่รู้ขั้นตอนเปลี่ยนบัญชี ตอนนี้ทำได้เต็มรูปแบบ

**ทางหลัก — สลับก่อนเปิดเบราว์เซอร์ (ไม่เสียงานสักใบ)**

```
_flow_pick_account()   อ่านยอดเครดิตที่จดไว้ตอนจบรอบก่อน
                       ไม่พอ → สลับบัญชี → ที่นั่งได้โฟลเดอร์ใหม่
```

ที่ทำได้เพราะเพิ่มการ **จดเครดิตลงทะเบียนบัญชีทุกครั้งที่จบรอบ** ของเดิมจด
เฉพาะตอนที่รู้ว่าไม่พอแล้ว ซึ่งสายเกินไป

**ตาข่ายรับ — สลับกลางทาง (เฉพาะตอนยอดที่จดไว้ไม่ทันสมัย)**

เจอเครดิตไม่พอหลังเปิดเบราว์เซอร์แล้ว → สลับบัญชี → โยน `SwitchAccount`
ออกมาให้รอบนอก **ปล่อยล็อกก่อน** แล้วเริ่มรอบใหม่ด้วยโฟลเดอร์ใหม่

ต้องออกมาปล่อยล็อกก่อนเสมอ เพราะโฟลเดอร์ใหม่มาคู่กับชื่อล็อกใหม่ —
เปิดโฟลเดอร์ใหม่ทั้งที่ยังถือล็อกเก่า = งานอื่นที่ถือล็อกของโฟลเดอร์นั้น
จะเปิด Chrome ทับกัน

ลองได้สูงสุด **2 รอบ** รอบสองยังไม่พอก็หยุดแล้วแจ้ง ไม่วนไปเรื่อยๆ

**ไม่ปิดช่องเจนอีกแล้วถ้าสลับสำเร็จ** ของเดิมปิดทุกกรณี ทำให้ต้องมีคนมากดเปิด

## 3. สรุปงานค้างที่ต้องทำต่อทั้งหมด

### รอเจ้าของ

1. **ล็อกอิน 6 บัญชีที่เหลือ — ครั้งเดียวต่อใบ** สั่ง
   `python flow_login.py โปรไฟล์` แล้วล็อกอินในหน้าต่างที่เด้งขึ้นมา
   ทำทีละใบก็ได้ ไม่ต้องทำรวดเดียว **หลังจากนี้ระบบสลับเองตลอด ไม่ต้องมีคนอยู่**
2. **แก้ 4 จุดที่ขัดกันในคำสั่งของ custom GPT** ที่ chatgpt.com (จุดเด่น 3 ข้อ
   กับ 4 ข้อ · กติกาตัวหนังสือที่ขัดกันเอง · คำสั่ง "ชั้นวาง" ที่ค้างจากของเก่า ·
   บังคับพื้นหลังบ้านมินิมอล) และเช็คสถานะ "Updates pending"
3. **ตัดสินว่าจะให้โชว์สถานะโปรไฟล์บนหน้าเว็บไหม** — ฝั่งงานพร้อมแล้ว
   (`flow_accounts.board()` คืน `profile_ready` · `profile_dir` · `ready`)
   ถ้าเอา ผมส่งสเปคให้สายกลางทำหน้าเว็บให้ (ตามกติกาข้อ 7.1.1)

### รอเราทำต่อ

4. **สตอรีบอร์ด 57 ใบรอโควตารูป ChatGPT** — ช่องสตอรีบอร์ดพักอัตโนมัติอยู่
   จะเปิดเองเมื่อโควตากลับมา
5. **61 ใบที่ทำเสร็จแล้วยังใช้กติกาเก่า** (พรีเซนเตอร์อยู่แค่ฉาก 1 กับ 5 ·
   บทพูดโทนเก่า) ต้องเจนใหม่
6. **ยังไม่เคยเห็นผลของกติกาพรีเซนเตอร์ใหม่** ("ใช้สินค้าจริงทุกฉาก") กับรูปจริง
   — โควตาหมดก่อน
7. **F5-TTS-THAI ลงไว้แล้วแต่ยังไม่เคยรัน** — แผนคือโคลนเสียงอ้างอิง Aoede
   เพื่อฟังเสียงตัวอย่างฟรีก่อนเจนจริง
8. **ตัวแปลงบทพูดปกติ → คำอ่านตอนแก้** ยังไม่ได้ทำ (ต้องวิ่งไปถาม ChatGPT)
   สายกลางทำหน้าโชว์อย่างเดียวไปก่อนแล้ว
9. **`SPEECH_MAX_CHARS = 135` แน่นเกินไป** — วัดความเร็วพูดจริงของ Veo ได้
   15.8 ตัวอักษร/วินาที แต่โค้ดคิดที่ 13.5 และมีคลิปยาว 170 ตัวอักษรอยู่จริง

## 4. ลิงก์ทั้งหมดที่นำไปใช้ต่อ

### คำสั่งที่ใช้บ่อย

```bash
python flow_login.py โปรไฟล์ --ดู                    # ใบไหนพร้อมแล้วบ้าง
python flow_login.py โปรไฟล์                         # ไล่ตั้งค่าทุกใบที่ยังไม่พร้อม
python flow_login.py โปรไฟล์ --อีเมล x@gmail.com     # เฉพาะใบเดียว
python flow_accounts.py board                        # บัญชี · เครดิต · ใบที่ใช้อยู่
python restart_clip.py                               # รีสตาร์ตสายคลิป (8877)
pythonw flow_accounts_window.py                      # หน้าต่างกรอกบัญชี (มี shortcut บน desktop)
```

### พาธไฟล์

```
data/flow_profiles/<ชื่อจากอีเมล>/    โปรไฟล์ Chrome ของแต่ละบัญชี
data/flow_gen_profile/                โปรไฟล์ของใบแรก (ล็อกอินค้างอยู่แล้ว)
data/flow_browser_profile2/           ช่องที่ 2 — ไม่ถูกแตะ
data/flow_accounts.bin                รหัสผ่าน (เข้ารหัสด้วยบัญชี Windows เครื่องนี้)
data/flow_accounts.json               สถานะ · เครดิต · ธงพร้อมใช้ (ไม่มีรหัสผ่าน)
data/clip_server.log                  log ของสายคลิป
```

### ไฟล์โค้ดที่แก้

```
flow_accounts.py    ทะเบียนบัญชี + โปรไฟล์
flow_worker.py      flow_seat() เลือกโฟลเดอร์ตามบัญชีที่ใช้อยู่
flow_login.py       คำสั่ง "โปรไฟล์" + account_on_page() + profile_check()
clip_app.py         _flow_pick_account() · _flow_switch_account() · SwitchAccount
```
