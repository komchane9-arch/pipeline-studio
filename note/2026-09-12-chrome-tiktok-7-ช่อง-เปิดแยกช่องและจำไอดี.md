**11–12 กันยายน 2569** · เจ้าของสั่ง *"ทำ chrome ตรง tiktok ไว้ 7 chrome
ทำให้สามารถกดเรียกดูและจำ ไอดี tiktok ที่ล้อคอินแยกแต่ chrome อันนี้จะเอาไว้
ลง tiktok ผ่าน chrome ในคอม แยกจากการลงผ่านมือถือ"*

## 1. สรุปข้อมูลทั้งหมด

### ทำไมต้องแยกโฟลเดอร์ทางเดียว

ของเดิม `flow_worker.login_tiktok()` ให้ล็อกอิน TikTok ในโปรไฟล์เดียวกับ Flow
ซึ่งใช้ได้บัญชีเดียว เพราะคุกกี้ TikTok มีชุดเดียวต่อโปรไฟล์ — วิธีเดียวกับที่
ทำกับบัญชี Google Flow เมื่อ 10 ก.ย. ซึ่งพิสูจน์แล้วว่าสลับบัญชีได้จริง

### ตรวจแล้วว่าเครื่องนี้ยังไม่มีบัญชี TikTok ล็อกอินค้างไว้เลย

ไล่ดูคุกกี้ทุกโปรไฟล์ในเครื่อง — ไม่มี `sessionid` หรือ `sid_tt` สักตัว

```
flow_browser_profile    คุกกี้ tiktok 9 ตัว   ทั้งหมดเป็นคุกกี้ติดตาม
flow_browser_profile2   0 ตัว
flow_browser_profile3   6 ตัว
flow_gen_profile        6 ตัว
```

### กับดักที่เจอตอนไปดูว่า TikTok วางชื่อบัญชีไว้ตรงไหน

หน้าแรก tiktok.com **ตอนยังไม่ล็อกอิน** มีชื่อบัญชีคนอื่นฝังมาด้วย 3 ชื่อ

```
__DEFAULT_SCOPE__.webapp.updated-items.0.author.uniqueId = armkiss
__DEFAULT_SCOPE__.webapp.updated-items.1.author.uniqueId = _ply01
__DEFAULT_SCOPE__.webapp.updated-items.2.author.uniqueId = wan.vogvax
```

เอาตัวอ่านแบบ "ไล่หาทั้งก้อน" มารันกับข้อมูลชุดนี้ → คืน **`@armkiss`** ทันที
ทั้งที่ไม่ได้ล็อกอินเลย ถ้าปล่อยไว้ ช่องนั้นจะถูกจดว่าเป็นบัญชีคนแปลกหน้า
แล้ววันที่เริ่มลงคลิปผ่านคอมจริง คลิปจะขึ้นผิดช่องแบบถอนไม่ได้

หน้า Studio ตอนยังไม่ล็อกอินถูกไล่ไปหน้าเข้าสู่ระบบ และมี `uniqueId` **0 ที่**
→ จึงใช้หน้า Studio เป็นหน้าอ่านไอดี ไม่ใช่หน้าแรก

### บั๊กใหญ่ที่สุด — ระบบไม่มีวันรู้ว่าเจ้าของปิดโครมแล้ว

```
อาการ      สั่งปิดโครมแล้วระบบตอบว่าล้มทุกครั้ง ทั้งที่หน้าต่างหายไปจริง
ทำไม 1     ตัวตรวจรอจนไม่เหลือหน้าต่างของโปรไฟล์นี้ แต่มันไม่เคยหมด

           อีก 2 บานขนาด 0x0 ไม่มีชื่อ (Chrome_WidgetWin_0)
ทำไม 3     Chrome แขวนบานซ่อนไว้เบื้องหลังเสมอ และไม่ปิดตามคำสั่ง

Corrective ถามใหม่ว่า "มีบานที่คนเห็นบนจอไหม" ซึ่งมีเฉพาะตอนเปิดจริง
Preventive แยกเป็น _is_real_window() ที่เทสได้โดยไม่ต้องมี Chrome + เทส
```

ผลข้างเคียงที่ใหญ่กว่าอาการ — ฟีเจอร์ "ปิดแล้วจำไอดี" รอสัญญาณนี้อยู่
จึงไม่เคยทำงานเลย และฝั่งเครดิต Flow ที่ทำไปเมื่อวานก็รอสัญญาณเดียวกัน

```
ก่อนแก้   นับ 3 หน้าต่าง · สั่งปิดรอ 10.0 วิ แล้วตอบว่าล้ม
หลังแก้   นับ 1 หน้าต่าง · สั่งปิด 0.3 วิ สำเร็จ
```

## 3. สรุปงานค้างที่ต้องทำต่อทั้งหมด

### รอเจ้าของ

- **ล็อกอิน TikTok ในช่องที่ต้องการ** — ผมทำแทนไม่ได้ (ห้ามกรอกรหัสผ่าน
  และห้ามสร้างบัญชีแทนคนอื่น) กดเปิดช่อง → ล็อกอิน → ปิด แล้วระบบจำให้เอง
- **คอนเฟิร์มสเปคหน้าเว็บ** `SPEC-ช่อง-chrome-tiktok.md` ก่อนส่งสายกลาง

### รอเราทำต่อ

- **การอ่านไอดีตอนล็อกอินแล้ว ยังไม่เคยสำเร็จสักครั้ง** — ที่อยู่ที่ใช้คือ
  `webapp.app-context.user.uniqueId` ซึ่งยืนยันแล้วว่า**ไม่มี**ตอนยังไม่ล็อกอิน
  แต่ยังไม่ได้ยืนยันว่า**มี**ตอนล็อกอินแล้ว ถ้ารอบแรกอ่านไม่ออก หลักฐานจะจด
  ให้เองว่าชื่อบัญชีไปโผล่ตรงไหน แก้จบในรอบเดียว
- ต่อสายช่องพวกนี้เข้ากับการลงคลิปผ่านคอมจริง (ยังไม่ได้เริ่ม)
- `tiktok_product_link.py` ยังไม่ได้ใช้ `screen_read`
- ที่ว่างในเครื่อง 15 GB · `data/evidence` โตขึ้นเรื่อยๆ

## 4. ลิงก์ทั้งหมดที่นำไปใช้ต่อ

```bash
python tiktok_chromes.py              # ดูทั้ง 7 ช่อง
python tiktok_chromes.py เปิด 1       # เปิดช่อง 1 เพื่อล็อกอิน
python tiktok_chromes.py อ่าน         # ไล่อ่านไอดีทุกช่อง
python test_tiktok_chromes.py         # เทสตัวอ่านไอดี ไม่ต้องเปิดเบราว์เซอร์
python test_chrome_view.py            # เทสตัวตรวจหน้าต่าง
python evidence.py list --tag tiktok  # ภาพตอนอ่านไอดีไม่ได้
```

ที่อยู่ที่หน้าเว็บเรียก (พอร์ต 8877)

```
GET  /api/tiktok/chromes
POST /api/tiktok/chromes/open      {"slot": 1}
POST /api/tiktok/chromes/refresh   {"slot": 1}  หรือ  {}
```

โฟลเดอร์โปรไฟล์: `data/tiktok_profiles/tiktok1` … `tiktok7`
ไฟล์จดไอดี: `data/tiktok_chromes.json`
