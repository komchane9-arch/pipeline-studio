# พิสูจน์ตัวอ่านไอดี TikTok บนหน้าเว็บจริง โดยไม่ต้องมีบัญชี

**12 กันยายน 2569** · ต่อจาก [Chrome ของ TikTok 7 ช่อง](2026-09-12-chrome-tiktok-7-ช่อง-เปิดแยกช่องและจำไอดี.md)

งานค้างข้อเดียวที่เหลือคือ *"อ่านไอดีตอนล็อกอินแล้ว ยังไม่เคยสำเร็จสักครั้ง"*
ซึ่งถ้ารอบัญชีจริงอย่างเดียวก็ทำอะไรไม่ได้เลย จึงไปหาหลักฐานมาแทน

---

## 1. สรุปข้อมูลทั้งหมด

### ทำไมเรื่องนี้ปล่อยไว้ไม่ได้

ตัวอ่านนี้เป็นตัวตัดสินว่าคลิปจะขึ้นช่องไหน **อ่านผิด = คลิปขึ้นผิดช่อง
แบบถอนไม่ได้** ชนิดเดียวกับที่ Facebook Reels หยิบรูปสินค้าไปโพสต์เมื่อ 10 ก.ย.

### หลักฐาน 3 ชั้น ทั้งหมดวัดจากของจริง

**ชั้นที่ 1 — โค้ดของ TikTok เองอ่านที่อยู่นี้**

ดึงบันเดิลของ TikTok มาค้น (76 ไฟล์) เจอใน `index.js`

```js
zr(["__$UNIVERSAL_DATA$__","__DEFAULT_SCOPE__","webapp.app-context","user","storeRegion"])
```

แปลว่าก้อน `user` อยู่ตรงที่เราอ่านจริง ไม่ใช่ที่เราเดาเอง

**ชั้นที่ 2 — ก้อนนั้นไม่มีตอนยังไม่ล็อกอิน**

ยิงที่อยู่ที่โค้ดเขาเรียกเอง `/node-webapp/api/common-app-context`

```
ตอนยังไม่ล็อกอิน -> มี 16 ช่อง (language, region, appId, csrfToken, ...)
                    ไม่มีก้อน user เลย
```

= ตรงตามกติกา 2.3.1 "ดูของที่มีเฉพาะตอนสำเร็จ"

**ชั้นที่ 3 — ชื่อช่องที่เก็บไอดีคือ `uniqueId`**

หน้าเดียวกันนั้น ข้อมูลของคนอื่นในฟีดก็ใช้ชื่อช่องนี้

```
__DEFAULT_SCOPE__.webapp.updated-items.0.author.uniqueId = armkiss
```

และรับชื่อที่สะกดต่างไว้ด้วย (`unique_id` · `uniqueID`) ถ้าไม่มีสักแบบ
จะฟ้องพร้อมรายชื่อช่องที่มีจริง ไม่เดา ไม่เงียบ

---

## 2. สรุปผลงานทั้งหมดในแชทนี้

### คำสั่งพิสูจน์ที่รันซ้ำได้ (commit `852a73a`)

```bash
python tiktok_chromes.py พิสูจน์
```

เปิดหน้า TikTok จริง แล้ววัดสองด้าน**บนหน้าเดียวกัน**

```
ก) วางชื่อบัญชีคนอื่นเป็นกับดัก 6 ชื่อ   -> ต้องปฏิเสธ         ผ่าน
ข) เติมก้อนบัญชีแบบตอนล็อกอินแล้ว     -> ต้องได้ @komchan.shop  ผ่าน
```

ข้อ (ข) เติมลงในข้อมูลเดิมของหน้าจริง **ไม่ได้แต่งหน้าขึ้นใหม่** จึงพิสูจน์
ได้ทั้งเส้น ตั้งแต่ดึงข้อมูลจากหน้า แกะ ไล่ที่อยู่ ไปจนตรวจรูปแบบไอดี

### กับดักต้องวางเองทุกรอบ

รอบแรกที่ลอง ฟีดหน้าแรกมีชื่อคนอื่น **0 ชื่อ** ซึ่งจะ "ผ่าน" ทั้งที่ไม่ได้
ทดสอบอะไรเลย — ฟีดเปลี่ยนทุกวัน จึงต้องวางกับดักเองให้มีแน่นอน

### พิสูจน์ว่าคำสั่งนี้จับของพังได้จริง

```
เอาตัวอ่านแบบไล่หาทั้งก้อนใส่กลับ  ->  คืน @pwrinssua (คนแปลกหน้า) · รหัสจบ 1
โค้ดปกติ                          ->  รหัสจบ 0
```

## 3. สรุปงานค้างที่ต้องทำต่อทั้งหมด

### รอเจ้าของ

- **ล็อกอิน TikTok อย่างน้อย 1 ช่อง** — ทำแทนไม่ได้ (ห้ามกรอกรหัสผ่าน
  และห้ามสร้างบัญชีแทน) กดเปิดช่อง → ล็อกอิน → ปิด แล้วระบบจำให้เอง
- **คอนเฟิร์มสเปคหน้าเว็บ** `SPEC-ช่อง-chrome-tiktok.md` ก่อนส่งสายกลาง

### รอเราทำต่อ

- ต่อสายช่องพวกนี้เข้ากับการลงคลิปผ่านคอมจริง (ยังไม่ได้เริ่ม)
- `tiktok_product_link.py` ยังไม่ได้ใช้ `screen_read`
- ที่ว่างในเครื่อง 15 GB · `data/evidence` โตขึ้นเรื่อยๆ

## 4. ลิงก์ทั้งหมดที่นำไปใช้ต่อ

```bash
python tiktok_chromes.py พิสูจน์      # พิสูจน์ตัวอ่านบนหน้าเว็บจริง (รหัสจบ 0 = ผ่าน)
python tiktok_chromes.py              # ดูทั้ง 7 ช่อง
python tiktok_chromes.py เปิด 1       # เปิดช่อง 1 เพื่อล็อกอิน
python test_tiktok_chromes.py         # เทสข้อมูลแช่แข็ง ไม่ต้องต่อเน็ต
```
