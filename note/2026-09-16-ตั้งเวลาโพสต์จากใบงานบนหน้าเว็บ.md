เจ้าของสั่ง *"เพิ่มฟังก์ชั่นตั้วเวลาโพสต์ในใบงานที่หน้าเว็ปให้ด้วย"*
แล้วสั่งต่อว่า *"ทั้ง 2 เครื่องเลยนะ"*

commit `e2b6d7a` · เวอร์ชันหน้าเว็บ `4b4be043`

## ของเดิมเป็นยังไง

ตั้งเวลาโพสต์ได้ทาง Telegram อย่างเดียว บนหน้าเว็บมีแต่ปุ่ม **"โพสต์เลย"**
ใบงานที่รออยู่จึงมีทางเดียวคือนั่งกดเองตอนถึงเวลา

## ของใหม่

ทุกใบที่ยังโพสต์ได้ (รอโพสต์ · หยุดไว้ · ล้มเหลว) มีแถวใหม่อยู่**เหนือแถวปุ่ม**
เพราะ "จะโพสต์เมื่อไร" ต้องตัดสินใจก่อน "กดโพสต์"

```
[ ช่องเลือกวันเวลา ]   ⏰ ตั้งเวลา   ล้างเวลา   ← ข้อความบอกผล
```

- ปุ่ม **ล้างเวลา** โผล่เฉพาะตอนมีเวลานัดอยู่จริง
- ตั้งแล้วบนการ์ดขึ้น `⏰ นัดโพสต์ 14:38 · อีก 3 ชม. 59 นาที`
- ล้างแล้วกลับเป็น `⏰ ไม่ได้ตั้งเวลา — กด "โพสต์เลย" ถึงจะเริ่ม`
- ช่องเวลาจะ**ไม่ถูกเขียนทับขณะกำลังพิมพ์** (การ์ดวาดใหม่ทุกวินาที ถ้าทับจะพิมพ์ไม่ทัน)

### รับเวลาได้หลายแบบ

| พิมพ์มาแบบไหน | ได้อะไร |
|---|---|
| ค่าจากช่องเลือกของเบราว์เซอร์ | ตามนั้น |
| `20:30` | วันนี้ 20:30 (ถ้าเลยแล้วเป็นพรุ่งนี้) |
| `9/8 20:30` | วันที่ 9 เดือน 8 |
| `+30` | อีก 30 นาที |
| `-` หรือเว้นว่าง | ยกเลิกเวลา |

**เวลาที่ผ่านไปแล้วตอบ 400 พร้อมบอกเหตุผล** ไม่ใช่รับไว้เงียบๆ แล้วไม่ยิง

### ทำไมถึงใช้ได้ทั้งสองบัญชีโดยไม่ต้องบอกว่าบัญชีไหน

ที่อยู่ใหม่ `POST /api/fb/jobs/<รหัสใบ>/schedule` ครอบด้วย `_job_ctx()`
ซึ่งเปิดดูทีละบัญชีว่ารหัสใบนี้อยู่ในแฟ้มของใคร — **ไม่เดาว่าเป็นบัญชีแรก**
และหาไม่เจอก็ตอบ 404 ไม่ใช่ 500

## บั๊กที่เจอระหว่างทาง — "สั่งซ่อนแล้วแต่ยังโผล่"

ตอนทดสอบบนโปรไฟล์ Preaw พบว่าการ์ด **"⚪ ยกเลิกแล้ว"** ก็ยังตั้งเวลาได้
แล้วขึ้นข้อความว่า *"ตั้งเวลาโพสต์ 16/09 13:39 แล้ว"* ทั้งที่ตัวตั้งเวลาหยิบเฉพาะ
ใบที่ยังรอโพสต์ — **ป้ายที่โกหก** (ข้อ 2.3.1)

### ไล่ทำไม

1. **ทำไมตั้งเวลาบนใบที่ยกเลิกแล้วได้** → แถวตั้งเวลาโผล่อยู่ ทั้งที่โค้ดสั่งซ่อนไปแล้ว
2. **ทำไมสั่งซ่อนแล้วไม่ซ่อน** → วัดในเบราว์เซอร์จริงได้ `hidden:true` แต่
   `display:flex` · `offsetWidth:1290`
3. **ทำไม display ยังเป็น flex** → กฎ `[hidden]` ของเบราว์เซอร์อยู่ชั้นล่างสุด
   คลาส `.fc-sched { display:flex }` ที่ผมเขียนเองทับมันทันที
4. **ทำไมถึงไม่รู้ตัว** → ฝั่งโค้ดสั่งซ่อนสำเร็จทุกครั้ง มันจึงเชื่อว่าซ่อนแล้วจริง
   — **"สั่งแล้ว" ไม่เท่ากับ "เกิดขึ้นจริง"**
5. **รากเหง้า** → บั๊กชนิดนี้เกิดกับ**ทุกคลาสที่ตั้ง display แล้วถูกสั่งซ่อนด้วย
   `hidden`** และในไฟล์นี้เคยเกิดมาแล้ว **3 ครั้ง** โดยสองครั้งแรกแก้เฉพาะจุด
   (`.screen-card[hidden]` บรรทัด 267 · `.tab-area[hidden]` บรรทัด 574)
   มันจึงกลับมาใหม่ทุกครั้งที่มีคนเขียนคลาสใหม่

### วัดจริงก่อนแก้ — ทั้งหน้ามี 3 จุดที่ซ่อนไม่ติด

| จุด | ควรซ่อนตอนไหน | ผลที่เกิดจริง |
|---|---|---|
| `#shopeeResult` | ยังไม่ได้ดึงสินค้า | กล่อง "ชื่อสินค้า / รูปที่จะเอาไปใช้" โผล่ค้างทั้งที่ว่าง |
| `#approvalActions` | ยังไม่มีอะไรให้อนุมัติ | ปุ่ม "✅ อนุมัติ — ส่งไปทำสตอรีบอร์ด" กดได้ทั้งที่ไม่มีงาน |
| `.fc-sched` | ใบจบ/ยกเลิกแล้ว | ตั้งเวลาได้ แล้วขึ้นว่าตั้งสำเร็จ ทั้งที่ไม่มีอะไรยิง |

**สองจุดแรกอยู่บนแท็บ ① Input ซึ่งเป็นงานของสายคลิป** ไม่ได้เกิดจากงานรอบนี้
แต่เจอพร้อมกันเพราะรากเดียวกัน

### Corrective + Preventive

**Corrective** — แถวตั้งเวลาซ่อนจริงบนใบที่จบ/ยกเลิกแล้ว
**Preventive** — แก้ที่รากทีเดียวแทนการไล่แก้รายคลาส

```css
[hidden] { display: none !important; }
```

ถ้ามีกฎนี้ตั้งแต่แรก ทั้งสามจุดจะไม่เกิดเลย และคลาสใหม่ที่ใครเขียนต่อจากนี้
ก็จะไม่เกิดอีก — ตอบข้อ "แก้ตรงนี้แล้วปัญหาประเภทนี้จะไม่กลับมา" ได้จริง
