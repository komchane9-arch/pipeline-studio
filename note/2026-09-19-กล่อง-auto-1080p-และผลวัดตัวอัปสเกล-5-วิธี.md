# 19 ก.ย. 2569 — กล่อง Auto 1080P และผลวัดตัวอัปสเกล 5 วิธีบน i5-13500

---

## บทสนทนาทั้งหมด

**เจ้าของสั่ง (แทรกกลางงานอื่น)**

> *"ผมอยากจะเพิ่ม flow ขึ้นมาตัวนึง โดยหลังจากตรวจคลิปเสร็จ จะมีกล่องทำคลิปให้เป็น
> 1080P เพื่อที่จะให้คลิปได้ 1080P ทุกคลิป โดยใช้ model ai local ทีนี้หาข้อมูลให้หน่อย
> model ai local มีตัวไหนบ้าง พร้อมข้อดีข้อเสีย ตอนนี้ผมมีแค่ I5-13500 ในการรัน
> โดยทำเปรียบเทียบ ถ้า up 360 to 1080 และ 720 ไป 1080 พร้อมบอกความสวยของคลิป
> ความเหมือนของต้นฉบับ และเวลาในการทำด้วย"*

พร้อมรูปวาดผัง: `เจน clip` และ `Manual` → `ตรวจ` → `Auto 1080P`

**ระหว่างทางเจ้าของตัดสิน 2 ครั้ง**

1. *"จะให้โหลดตัวอัปสเกล AI มาวัดเทียบไหม"* → **"โหลดทั้ง 3 ตัว"**
   และ *"คลิป 360p ที่ข้อมูลหายไปเยอะ จะเอายังไง"* → **"ไม่เอา เอาแค่ 720P เลย"**
2. หลังเห็นผลวัดและภาพเทียบ → ***"เอา ffmpeg ทำต่อเลย"***

**เจ้าของถามเพิ่ม** *"มีรูปเปรียบเทียบที่ตัวสินค้าไหม"* → ทำให้ แต่ตอบตรงๆ ว่า
ตัวสินค้าดูไม่ออกเพราะเป็นสีพื้นเรียบ

## 1. สรุปข้อมูลทั้งหมด

### สภาพเครื่องที่ยืนยันแล้ว

| | |
|---|---|
| CPU | Intel i5-13500 · 20 คอร์ที่ใช้ได้ |
| การ์ดจอแยก | **ไม่มี** — torch เป็นรุ่น CPU ล้วน (`2.14.0+cpu`) |
| การ์ดจอออนบอร์ด | **Intel UHD 770 · ใช้ได้จริงผ่าน Vulkan** (มี `vulkan-1.dll` ในเครื่อง) |
| ffmpeg | 8.1.2 |
| venv งานภาพ | `_vision_env` มี torch + torchvision + opencv-contrib 4.11 (มี `dnn_superres`) |

### คลิปที่มีในเครื่อง

```
1080×1920   329 ใบ
 720×1280     9 ใบ     ← ใบที่ต้องขยาย
```

**การมีคลิป 1080p ของจริง 329 ใบคือสิ่งที่ทำให้วัดได้แม่น** — เอามาย่อลงเป็น 720
แล้วอัปกลับ เทียบกับตัวจริง จึงตอบได้ว่า "เหมือนต้นฉบับแค่ไหน" โดยไม่ต้องเดา

### วิธีวัดและด่านคุมความน่าเชื่อถือ

```
คลิป 1080×1920 ของจริง  →  ย่อเป็น 720×1280  →  อัปกลับเป็น 1080×1920  →  เทียบกับตัวจริง
```

**ใส่ตัวคุมด้วย** — วิธีขยายแบบหยาบที่สุด (nearest neighbor) ต้องได้คะแนนต่ำกว่าชัดเจน
ไม่งั้นแปลว่าตัววัดแยกดี/แย่ไม่ออก แล้วตัวเลขทั้งชุดใช้ไม่ได้

```
720 → 1080 lanczos   PSNR 45.48   SSIM 0.9930
720 → 1080 หยาบ      PSNR 40.97   SSIM 0.9909     ← ต่ำกว่า 4.5 คะแนน ✅ ตัววัดใช้ได้
360 → 1080 lanczos   PSNR 39.61   SSIM 0.9867
360 → 1080 หยาบ      PSNR 37.72   SSIM 0.9837     ← ต่ำกว่า 1.9 คะแนน ✅
```

### ผลวัด 5 วิธี (720 → 1080 · คลิป 10 วินาที 240 เฟรม)

| วิธี | วินาที/เฟรม | นาที/คลิป | PSNR | SSIM |
|---|---|---|---|---|
| waifu2x (cunet) | 5.18 | 20.7 | **48.39** | 0.9947 |
| **ffmpeg lanczos** | 0.20 | **0.8** | **46.09** | 0.9935 |
| Real-ESRGAN x4plus | 123.37 | 493.5 | 43.99 | 0.9929 |
| Real-ESRGAN animevideov3 | 3.38 | 13.5 | 40.88 | 0.9930 |
| Real-CUGAN | 5.25 | 21.0 | 37.57 | 0.9872 |

**ทุกตัว AI รันบนการ์ดจอออนบอร์ดผ่าน Vulkan จริง** ยืนยันจากข้อความที่โปรแกรมพิมพ์ออกมา
`[0 Intel(R) UHD Graphics 770] queueC=0[1] queueG=0[1] queueT=0[1]`

### ข้อค้นพบที่สวนสามัญสำนึก

**ตัว AI สามในสี่ตัวได้คะแนนแย่กว่า ffmpeg ธรรมดา**

เพราะมันไม่ได้ขยายภาพเฉยๆ แต่ **เดารายละเอียดขึ้นมาใหม่** — พอเดาไม่ตรงของจริง
คะแนนความเหมือนจึงตก ดูด้วยตาแล้วตัวอักษรไทย "ดูคม" กว่า แต่เป็นความคมที่มัน
วาดขอบขึ้นมาเอง ไม่ใช่ขอบเดิมของฟอนต์

**ตัวเดียวที่ชนะคือ waifu2x** ชนะ 2.3 คะแนน แต่ใช้เวลามากกว่า **26 เท่า**

**Real-ESRGAN x4plus ใช้ไม่ได้เลย** 8 ชั่วโมง 13 นาทีต่อคลิปหนึ่งใบ
ถ้าทำ 430 ใบคือ 147 วัน

### จุดที่ภาพต่างกันจริงมีจุดเดียว

ทำภาพเทียบ 4 จุด: ตัวหนังสือไทย · ขอบหมอน (ตัวสินค้า) · ผิวหมอน · ฉากหลัง

| จุด | ต่างกันไหม |
|---|---|
| **ตัวหนังสือไทยที่แปะทับคลิป** | **ต่างชัดเจน** — จุดเดียวที่ตัดสินได้ด้วยตา |
| ฉากหลัง (ก้านดอกไม้แห้ง) | ต่างเล็กน้อย เส้นบางเริ่มหนาขึ้น |
| ขอบหมอน · ผิวหมอน | **แยกไม่ออกเลย** |

**เหตุผล** — คลิปของเราสร้างด้วย Veo ซึ่งเนื้อภาพนุ่มอยู่แล้วตั้งแต่ต้นทาง
ไม่ใช่ภาพถ่ายกล้องจริงที่มีลายผ้า ลายไม้ ตัวอักษรบนกล่อง
ตัวอัปสเกลจึงไม่มีรายละเอียดให้กู้คืน

### เวลาจริงตอนใช้งานจริง ≠ เวลาตอนวัดเทียบ

```
ตอนวัดเทียบ   0.8 นาที/คลิป   (ประกอบจากภาพนิ่ง 240 ใบ)
ตอนใช้จริง    2.8 วินาที/คลิป  (แปลงคลิปตรงๆ บน 20 คอร์)
```

เร็วกว่าที่ประมาณไว้ 17 เท่า — คลิปค้างทั้งหมดใช้เวลาไม่กี่นาที ไม่ใช่ 5 ชั่วโมง

## 2. สรุปผลงานทั้งหมดในแชทนี้

### commit `9cedadc` — กล่อง Auto 1080P

**กระดานเป็น 12 กอง** แทรก `up1080` ระหว่างกองตรวจคลิปกับกองลง Shopee

| ไฟล์ | ทำอะไร |
|---|---|
| `clip_board.py` | กอง `UP1080` · `clip_short_side()` · `needs_1080()` · `up1080_fields()` · `UP1080_MIN_SIDE` (อ่านจาก `clip_check.MIN_SHORT_SIDE` ไม่เขียนเลข 1080 ซ้ำ) |
| `clip_app.py` | `_up1080_one()` · `_up1080_round()` · `_up1080_keeper()` · `_up1080_status()` · 3 ที่อยู่ |
| `SPEC-กล่อง-auto-1080p.md` | สเปคให้สายกลางทำหน้าเว็บ (ส่งไปแล้ว) |

**ที่อยู่ใหม่**

```
GET  /api/up1080                 สถานะกล่อง (มากับ /api/board ด้วย)
POST /api/up1080                 {"on": true/false} เปิด/ปิดอัตโนมัติ
POST /api/clips/{id}/up1080      สั่งขยายทีละใบ
```

### ด่าน 6 ชั้นที่กันไว้

1. **เก็บไฟล์เดิมทุกใบ** เป็น `<ชื่อ>-ก่อนขยาย.mp4` — คลิปหนึ่งใบจ่ายเครดิต Veo 15 หน่วย
2. **วัดความละเอียดไม่ได้ = ไม่ขยาย** เพราะ "วัดไม่ได้" ไม่ใช่ "ต่ำกว่าเกณฑ์" (กติกา 2.3.1 ข้อ 4)
3. **ตรวจไฟล์ที่ได้จริงก่อนสลับ** ไม่ถึงเกณฑ์ก็ลบทิ้งแล้วฟ้อง ไม่เอาไปทับของดี (ข้อ 2)
4. **ตรวจคลิปใหม่อัตโนมัติ** ไม่งั้นป้าย "ยังไม่ 1080p" ค้างทั้งที่แก้แล้ว
5. **ล้มแล้วพักใบไว้** ไม่วนลองใบเดิมทุก 90 วินาทีตลอดกาล
6. **ใบที่ลงครบสามที่แล้วไม่ขยาย** แต่ใบที่ยังเหลือที่ให้ลง **ยังขยาย** เพราะได้ 1080p
   สองที่ดีกว่าได้ศูนย์ที่

## 3. สรุปงานค้างที่ต้องทำต่อทั้งหมด

### รอเจ้าของ

1. **เติมเงิน Gemini** ที่ https://ai.studio/projects — คีย์ตายหมด 4 ใบ ข้อนี้บล็อกทุกอย่าง
2. **ปลดบล็อกบอท Telegram**
3. ตัดสินว่าจะให้ **ปลดพัก 46 ใบรอทำสตอรีบอร์ด** ไหม (ผมกดให้ได้ทันที)
4. ตัดสินว่าจะให้ **เปิดช่องเจนคลิป** ไหม (ผมกดให้ได้ทันที · เครดิต Flow เหลือ 305 = 20 คลิป)
5. จะหยุดคิว TikTok 319 ใบไว้ก่อนไหม จนกว่าตัวติดป้าย AI จะพร้อม

### รอเราทำต่อ

6. **ฟิลด์รายใบของกล่อง 1080P ยังไม่ได้ใส่ใน `/api/clips` และ `/api/clips/<id>`**
   — มี `up1080_fields()` พร้อมแล้ว รอสายกลางบอกว่าต้องใช้ไหม
7. หน้าเว็บกล่อง Auto 1080P — ส่งสเปคแล้ว รอสายกลางทำ
8. กล่อง ✋ Manual บนกระดาน (ปุ่มอัปไฟล์ + กดเสร็จ) — สายกลางกำลังทำ
9. ตัวติดป้าย AI ตอนโพสต์ TikTok — มีสเปคแล้ว **แต่ห้ามเริ่มก่อนเก็บผังจอ**
10. `publish_order.check()` มีรู ปล่อยให้ลง 2 ที่วันเดียวกันได้ 3 ใบ

### ยังไม่ได้พิสูจน์ — บอกตรงๆ

- **"ความสวย" ยังไม่ได้วัด** ตัวเลข PSNR/SSIM บอกได้แค่ "เหมือนต้นฉบับแค่ไหน"
  ภาพที่ AI เดาขอบให้คมอาจดูดีกว่าบนมือถือจริง แต่ไม่มีตัวเลขมายืนยัน
- **วัดกับคลิปใบเดียว** ยังไม่ได้ลองกับคลิปที่มีลายจริง (ทีวีที่มีตัวหนังสือบนจอ ·
  สายชาร์จที่มีตัวอักษรบนหัวปลั๊ก) ซึ่งอาจให้ผลต่างจากนี้
- **ยังไม่ได้ลอง OpenCV dnn_superres** (EDSR/FSRCNN) ถึงจะโหลดโมเดลมาแล้ว
  เพราะสามตัวแรกให้คำตอบชัดพอจะตัดสินใจแล้ว

```bash
# สถานะกล่อง
curl -s http://127.0.0.1:8877/api/up1080

curl -s -X POST http://127.0.0.1:8877/api/up1080 -H "Content-Type: application/json" -d "{\"on\":true}"

python -c "import clip_board,clip_store,studio_shared as sh; runs=clip_store.list_runs(sh.DATA_DIR)+clip_store.list_done(sh.DATA_DIR); print([r['item_id'] for r in runs if clip_board.needs_1080(r)])"
```
