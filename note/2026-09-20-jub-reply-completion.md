# จุ๊บ แจง: ทำคิวให้จบและเทียบการทำงานจริงกับโค้ด

ผู้ใช้สั่งให้ทำรายการนี้จนเสร็จ พร้อมนำจุดขาดกลับไปแก้โค้ด. คิวคือ Preaw Buchakorn ตอบ “คุ้มมากค่าาาา” ใต้ข้อความ “คุ้มมากค่ะ” ของจุ๊บ แจง ใน https://www.facebook.com/share/p/1BZdem2mYw/.

## Why-Why และสิ่งที่แก้

- ข้อผิดพลาดเริ่มต้นคือจับปุ่ม Reply ไม่ได้. ทดสอบสดพบปุ่มและยืนยัน “กำลังตอบกลับ จุ๊บ แจง” สำเร็จ; ยังไม่มี XML ขณะเกิดเหตุเก่าที่พิสูจน์ว่าปุ่มพ้นจอหรือถูกแบ่งแถวผิด.
- ตัวตรวจบัญชีเคยเปิด activity เดิมที่ค้างหน้าแชร์โพสต์ต่อ ไม่มี bottom tabs. เปลี่ยน queued reply และการตรวจบัญชีก่อนเส้นทางสำรองให้ fresh_start=True เพื่อเข้าฟีดก่อนตรวจโปรไฟล์.
- การทดสอบส่งจริงรอบ 12:02:54 หยุดก่อนพิมพ์: composer จริงเป็น android.widget.AutoCompleteTextView แต่ editor() ยอมรับเพียง EditText. เพิ่มการรองรับ editable field ชนิด AutoComplete/MultiAutoComplete และยังบังคับ focused เพียงหนึ่งช่อง.
- ช่องจริงคืนชื่อ mention เป็น “กล่าวถึง, จุ๊บ แจง, นอกเหนือการกล่าวถึง”. หลังพิมพ์ในรอบ 12:05:31 ข้อความอ่านกลับเป็น “กล่าวถึง, จุ๊บ แจง, นอกเหนือการกล่าวถึง,  คุ้มมากค่าาาา”. ตัวคั่น accessibility ถูกนำไปนับเป็นข้อความ จึงหยุดก่อนส่ง. แปลงเฉพาะ wrapper และตัวคั่นหนึ่งชุดกลับเป็นชื่อ+ข้อความจริง โดยรักษาช่องว่างที่พิมพ์ไว้ และตรวจคำตอบเต็มตามเดิม.
- เอาเนื้อหา AutoCompleteTextView ออกจากหลักฐานหลังส่งด้วย เพื่อไม่เข้าใจว่าข้อความที่ยังอยู่ในช่องพิมพ์คือคำตอบที่ส่งแล้ว.
- เพิ่มการตรวจคำตอบเดิมที่แสดงอยู่ใต้แม่คอมเมนต์ตรงตัวก่อนแตะ Reply. หากยืนยันได้จะไม่พิมพ์ซ้ำ. รายการที่มี submitted marker ยังคงตรวจผลอย่างเดียว.
- เครื่องมือเฉพาะรายการ tools/diagnose_targeted_reply.py เก็บ XML ทุกช่วงและผลใน diagnostics/jub-reply-*. ใช้ phone lock, ตรวจ priority/โควต้า, ส่งเมื่อ --send และบันทึกผลด้วย receipt เดิม; รอบตรวจไม่ส่งเป็นค่าปริยาย.

## การทดสอบ

- Unit tests 12 รายการผ่าน: fresh account check, ไม่แตะ Reply เมื่อเห็นคำตอบเดิม, mention text ตาม XML จริง, ช่องที่โฟกัสกำกวมต้องหยุด, ตรวจข้อความเต็ม, ตัด editor ออกจากหลักฐานส่ง และกันส่งซ้ำเมื่อผลไม่ชัด.
- หลักฐานก่อนส่ง: แถวจุ๊บ แจงไม่มีปุ่มกางคำตอบ ในขณะที่แม่คอมเมนต์ข้างเคียงมี; verified_reply ไม่พบคำตอบที่ต้องส่ง. รอบที่ล้มจาก editor/ตัวคั่นไม่มี submitted marker และไม่กดส่ง.

## ตรวจผลหลังส่ง

- รอบ 12:07:33 ส่งแล้ว: XML 018 แสดงแม่คอมเมนต์จุ๊บ แจง y=676, คำตอบของ Preaw y=927 (เยื้อง x=165 จากแม่ x=33), เนื้อหา “จุ๊บ แจง  คุ้มมากค่าาาา”. คำตอบตรงกับ draft หลังแยก mention/ช่องว่าง.
- ตัวตรวจเดิมยังให้ false เพราะ `_comment_text_near` เรียง node ที่ y เท่ากันแล้วหยิบ inline mention “จุ๊บ แจง” ก่อน container ข้อความเต็ม. แก้ให้รวมข้อความตาม y และอ่านข้อความเต็มก่อน พร้อมไม่ตัดข้อความคอมเมนต์ที่ 60 ตัวในเส้นทาง visible_comments; เส้นทางนับยอดยังจำกัด 60 ตามเดิม.
- ใช้ XML หลังส่งจริงตรวจซ้ำด้วยโค้ดใหม่ได้ True. ใน DB มี submitted marker จึงไม่ส่งซ้ำ; เปิดโพสต์ตรวจยืนยันการคงอยู่จริงอีกรอบก่อนบันทึกสำเร็จ.
- Regression 17 รายการผ่านหลังแก้ parser รวมชนิดช่องพิมพ์, mention, ข้อความเต็มไม่ถูกแท็กย่อยบัง, fresh account guard และ caption path.

- เปิดโพสต์ใหม่แล้วพบว่าคำตอบถูกพับใต้ “ดูการตอบกลับ 1 รายการที่ จุ๊บ แจง ได้รับ...”. เพิ่มตัวกางคำตอบเฉพาะแถวแม่ที่ชื่อ+ข้อความตรงและปุ่มอ้างถึงชื่อเต็มนั้น พร้อมตรวจขอบเขต avatar; ใช้ทั้งก่อนส่งเพื่อกันซ้ำและการตรวจผลหลังส่ง. ไม่แตะปุ่มส่งระหว่าง verify.
- รอบ 12:13:33 เปิดโพสต์ใหม่ กางคำตอบ และยืนยันสำเร็จจริงเวลา 12:14:34 (`verification_only=true`). mark_reply_result บันทึก answered=1/sent และล้าง error; โควต้า Preaw จาก 8/50 เป็น 9/50 เหลือ 41. ส่งจริงเพียงรอบ 12:07:33; รอบหลังทั้งหมดตรวจอย่างเดียว.
