### Why-Why และขอบเขตข้อสรุป

1. Demi ไม่สำเร็จเพราะคำสั่ง swipe ผ่าน ADB ไม่คืนผลใน 30 วินาที.
2. ก่อน timeout มีหลายคำสั่ง/อุปกรณ์และระบบอื่นล้มพร้อมกัน ไม่ใช่เฉพาะคอมเมนต์นี้.
3. ยืนยันจาก Windows ว่าขณะนั้นเครื่องประสบ virtual-memory exhaustion และ paging file ไม่พอต่อการจัดสรร พร้อม Python MemoryError. เป็นคำอธิบายที่มีหลักฐานสนับสนุนมากสำหรับการล้มเป็นวงกว้าง แต่ไม่มี trace ภายใน ADB เพื่อพิสูจน์กลไกทุกขั้น.
4. ทำไมหน่วยความจำถูกใช้จนหมด/ทำไมการขยาย pagefile ไม่พอ: **ยังยืนยันสาเหตุรากไม่ได้**. ขาดค่า committed/limit, การเปลี่ยนขนาด pagefile และ private bytes ราย process ณ เหตุการณ์; ตัว Windows detector ก็ล้มก่อนทำรายงานสำเร็จ.
5. แนวทางที่แนะนำถ้าสั่งแก้: เพิ่มบันทึก committed/limit และผู้ใช้ private bytes สูงสุดแบบหมุนเวียน รวมทรัพยากรเครื่อง/ADB เมื่อ timeout; เพิ่ม guard พักงานก่อนวิกฤตและตรวจสถานะก่อน retry. การเพิ่ม pagefile เป็นการบรรเทาความเสี่ยง ไม่ได้พิสูจน์หรือแก้ memory leak. ไม่ควรสุ่มปิดโปรแกรมหรือโทษ Chrome/Python จากค่าปัจจุบัน.

รอบนี้ตรวจและบันทึกเท่านั้น ไม่แก้โค้ด ไม่เปลี่ยน pagefile ไม่รีสตาร์ต ไม่ส่ง Demi ซ้ำ.
