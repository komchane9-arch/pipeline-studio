## Why-Why

1. Nampet/Ulaiwun ขึ้น `reply_not_in_thread` ทั้งที่ส่งแล้ว → หน้าจออยู่ที่ “เกี่ยวข้องมากที่สุด” → ตัวค้นหาเดิมไม่ได้เปลี่ยนตัวกรอง → คำตอบที่ Facebook ซ่อนในมุมมองนี้ไม่อยู่ใน XML
   - `20260921-215642-Nampet/004.xml` ยืนยันตัวกรองเดิม; `010.png` ไม่มี expander ใต้ Nampet
   - หลังเลือกทั้งหมด `20260921-220107-Nampet/009.png` มี “ดูข้อความตอบกลับ 2 รายการ”
2. หลังเปลี่ยนตัวกรองก็ยังไม่ผ่าน → verifier เห็น parent ถัดไปแล้ว break ก่อนเรียกตัวกางคำตอบ → เธรดที่ยุบอยู่ถูกตีความว่าตรวจจบแล้ว
   - แก้ลำดับให้กาง exact author+body thread ก่อนรับ boundary และเริ่ม context ใหม่หลัง tap
   - เปลี่ยนข้อความไม่ให้กล่าวอ้างว่า “ตรวจครบเธรด” เมื่อเพียงอ่านส่วนที่ปรากฏ
3. Ruby รายงานไม่มี Reply → screenshot `20260921-215823-RubyOwl8377/008.png` มีปุ่มจริง → XML ใช้ `ปุ่ม, ตอบกลับ แตะสองครั้งเพื่อตอบกลับความคิดเห็น` ไม่ใช่รูปแบบระบุชื่อที่ parser รู้จัก
   - เพิ่ม label ที่พบจริง โดยยังบังคับ clickable และขอบเขตระหว่าง avatar ของแถว
4. Ruby หลังรองรับปุ่มแล้วกลับขึ้นไม่เจอโซนคอมเมนต์ → หลังเปิดคำตอบเก่า code เรียก finder ใหม่ → finder เลื่อนหาหัวตัวกรองจากกลางรายการจนหลุด target
   - เพิ่ม `in_comments=True` เฉพาะการ reacquire หลังเปิดเธรด อ่านแถวปัจจุบันใหม่ก่อน ไม่ใช้พิกัดเก่า ไม่ค้นหัวโซนซ้ำ
5. เพิ่มความเข้มงวด: prose parser ตัด URL จึงต้องตรวจ URL ของ draft ภายในแถวคำตอบเดียวกันด้วย ไม่ใช้ข้อความบางส่วนหรือ URL จากแถวข้างเคียง
